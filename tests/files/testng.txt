TestNg 
---------
Test for Next Generation 

TestNG is a popular testing framework for Java created by cedric- beust and inspired by JUNIT .

it has a new functionality that makes this framework more powerful and easier 

It is an open source framework for automation test in java .

It is used to write , organize and execute test cases for software application. 

It is used to design our test cases in a systematic  way . 



Advantages of testng 
-------------------------
-->It provide the default html report  and detailed report 
--> Easy to set priority (we can prioritized the test cases)
--> Easy to pass parameters(we can pass inputs as data from testNg.xml file using parameters)
-->Data provider is possible (we can pass the bulk of datas at a time for the positive and negative testcases 
combination )
-->cross browser testing (To check the compatibility and stability of the application) and parallel execution
is possible.
-->Automatically rerun the failed testcases. 
--> we can group the bulk of tescases and then we can skip or execute the testcases by using the group name . 
-->It will support private methods.
-->Assertion is possible (verify)

Annotations
 ---------------
Tesng anotations are markers in java that instruct the testing framework on how to execute test methods.


1)Before suite  
	Runs once before all test in the suite 

2)BeforeTest 
	Runs once before all the  test method in a <test> tag in testng.xml file 

3)BeforeClass  
	Runs once before all the test method in the class

4)BeforeMethod  
	Runs before each @Test method 

5)Test
	The actual test method
 
6)AfterMethod  
	Runs after each @Test method

7)AfterClass 
	Runs  once after all the test method in the class 

8)AfterTest 
	Runs  once after all the test method in a <test> tag in testng.xml
  
9)AfterSuite
	Runs once after all the test in th suite have completed

example 
-----------

Attributes 
------------
The testng attribute is a form of configuration parameters 

It can be set on testng annotations for different aspects of control over the running of tests.
 
It should  has to be within the rounded brackets next to @Test annotation .

It follow camel notation.

@Test(attributeName = "attributevalue")


1.priority :
	It allows you to define the order in which test methods should be executed.
	It ranges from -ve from +ve values

2.description :
	It allows you to add a actual description of the test method 
	we can describe our test cases

3.invocationCount:
	It defines the number of times a test method is performed 

4.enabled:
	the enabled attribute is used to enable or disable a test method 


5.dependsOnMethods :
	It defines dependencies between test method 
	It will depend upon another method 

6.alwaysRun :
	If we keep this attribute as true , it will help us to have a soft dependency.
	

7.timeOut :
	we are providing some time period for the particular test case to run within the seconds , 

8.invocationCount , timeOut :
	it will equally provide the time period for each one of the run . 

9.invocationCount ,invocationTimeOut:
	It will set the time period for overall run .

10.expectedExceptions =Exception.class:
	It will ignore the exception for the particular test cases.


example 
----------
package org.test;

import org.testng.annotations.Test;

public class Attributes {

	@Test (priority=-2,description = "Test case for login function",expectedExceptions = Exception.class)
	private void login() {
		System.out.println("Login functionality");
		System.out.println(10/0);
	}
	
	@Test(priority = -1,dependsOnMethods ="login",alwaysRun = true )
	private void homePage() {
	System.out.println("Home page Functionality");
	}
	
	@Test(priority = 0,invocationCount =2 ,invocationTimeOut  = 2000)
	private void productPage() {
		System.out.println("ProductPage Functionality");
	}
	
	@Test(priority = 1,timeOut =2000)
	private void addToCart() throws InterruptedException {
		Thread.sleep(2100);
	System.out.println("AddTocart Functionality");
	}
}

Assertion 
------------
1.In TestNG, assertions are lines of code that verify if a test passed or failed
2.If the condition becomes fail in assertion , it will throw an assertion error  immediately. 
3.It will halt my program execution.


verify 
-------
1."verify" refers to a method used to check if a specific condition on a web page is true
2.Even if the condition becomes fail , it will not throw any assertion error . 
3.It will not stop my program execution . 


Types of assertion 
---------------------
1.Hard assertion 
2. Soft assertion 


1.Hard Assertion 
-------------------
*it is a way of verifying that a certain piece of code is working as expected.
*When an assert statement is executed, it compares the actual outcome of a test with the expected outcome. 
*If the two outcomes match, the assert statement passes and the test continues. 
*If the actual outcome does not match the expected outcome, the assert statement fails and the test is halted. 
* the test is marked as failed.

2.Soft assertion 
------------------
*Soft assertions are the ones in which the test execution does not stop if the test does not meet the assertion 
condition. 

*The remaining tests are executed. All the above methods also work with soft assertions


common methods available is assert
--------------------------------------------
i) assertEquals ():
	
	This method takes a minimum of 2 arguments and can compare strings , Integers , 
	Doubles and many more variables 
ii)assertNotEquals()
	
	This method does the opposite of the assertEquals() method 

iii)assertTrue():
		
	This method varifies the boolean values returned by the  condition .If the boolean value is true ,then 
	the assertion passes the test cases 

iv)assertFalse():

	This method works the opposite of assrtTrue().If the boolean value returned by the condition is false , the
	assertion passes the test cases 

v)asserNull():

	This method verifies if the expected output is null and if not then the value returned is false 

vi)assertNotNull():

	This method works opposite to the asserNull() nd the assertion condition is met when the method validated the 
	expected output to be not null.

package annotations;

import org.jspecify.annotations.Nullable;
import org.openqa.selenium.By;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.WebElement;
import org.openqa.selenium.chrome.ChromeDriver;
import org.testng.Assert;
import org.testng.annotations.AfterMethod;
import org.testng.annotations.BeforeMethod;
import org.testng.annotations.Test;
import org.testng.asserts.SoftAssert;

public class AssertionDemo {
	WebDriver driver ;
	
	
	@BeforeMethod
	public void browserSetup() {
		driver = new ChromeDriver();
		driver.get("https://www.facebook.com/");
	}
	
	@Test
	public void verifyPageTitle() {
		
		@Nullable
		String title = driver.getTitle();
		
//		Assert.assertEquals(title, "Facebook – log in or sign up") hard asser
		
		//soft assert 
		
		SoftAssert s = new SoftAssert();
		
		s.assertEquals(title, "Facebook – log in or sign up", "page title verification failed");
		
		System.out.println("--verification completed--");
		
		
		s.assertAll();
		
	}
	
	
	@Test
	public void loginVerify() {
		WebElement login = driver.findElement(By.name("login"));
		
//		Assert.assertFalse(login.isDisplayed()); hard assert
		
		//soft assert 
		SoftAssert s = new SoftAssert();
		s.assertFalse(login.isDisplayed());
		System.out.println("login verification completed");
		
		s.assertAll();
	}
	
	
	@AfterMethod
	public void tearDown() {
		driver.quit();
	}
	
	
	
}

Listeners
---------
In TestNG, listeners are interfaces that monitor various events during the test execution cycle (such as a test starting, passing, or failing) and allow you to execute custom code in response

3 types 
---------
1.ITestListener 
2.IRetryAnalyzer 
3.IAnnotationTransformer

1.ITestListener 
---------------
It is an interface

Example
-------
package org.listeners;

import java.awt.AWTException;
import java.io.IOException;

import org.test.OrangrHrmUsingDataprovider;
import org.testng.ITestContext;
import org.testng.ITestListener;
import org.testng.ITestResult;

public class MyTestListener implements ITestListener{


	public void onStart(ITestContext context) {
	   System.out.println("On class started");
	  }
	
	public void onTestStart(ITestResult result) {
	    // not implemented
		System.out.println("On test started");
	  }
	
	
	public void onTestSuccess(ITestResult result) {
	    // not implemented
		System.out.println("On test success");
	  }
	
	public void onTestFailure(ITestResult result) {
	    // not implemented
		System.out.println("on test failure");
		try {
			OrangrHrmUsingDataprovider.captureCompleteScreenshot();
		} catch (AWTException e) {
			// TODO Auto-generated catch block
			e.printStackTrace();
		} catch (IOException e) {
			// TODO Auto-generated catch block
			e.printStackTrace();
		}
	  }
	
	public void onTestSkipped(ITestResult result) {
	    // not implemented
		System.out.println("on test skipped");
	  }
	
	
	public void onFinish(ITestContext context) {
	    // not implemented
		System.out.println("on class finish");
	  }
	
}

import java.awt.AWTException;

import org.jspecify.annotations.Nullable;
import org.openqa.selenium.By;
import org.testng.Assert;
import org.testng.annotations.Test;
import org.utility.BaseClass;
import org.utility.Utility;

public class OrangrHrmUsingDataprovider extends BaseClass{
	
	@Test(dataProviderClass = Utility.class , dataProvider = "getDatasFromExcel" )
	public void orangeHrmLogin(String username , String password) throws InterruptedException {
		driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(10));
		driver.findElement(By.name("username")).sendKeys(username);;
		driver.findElement(By.name("password")).sendKeys(password);
		driver.findElement(By.xpath("//button[@type='submit']")).click();
		
		Thread.sleep(2000);
		
		@Nullable
		String currentUrl = driver.getCurrentUrl();
		
		Assert.assertTrue(currentUrl.contains("dashboard"));
	}
	
	

	public static void captureCompleteScreenshot() throws AWTException, IOException {
		
		Robot r = new Robot();
		
		Dimension d = Toolkit.getDefaultToolkit().getScreenSize();
		
		Rectangle rect = new Rectangle(d);
		
		BufferedImage b = r.createScreenCapture(rect);
		
		File dest = new File("./screenshot/orangehrm"+System.currentTimeMillis()+".png");
		
		ImageIO.write(b, "png", dest);
	}

	

}

2.IRetryAnalyzer
--------------------
how to run the failed test cases
------------------------------------
i)using testng-failed.xml
ii)using IretryAnalyzer


example 
--------
package testNgListener;

import org.testng.IRetryAnalyzer;
import org.testng.ITestResult;

public class MyRetryListener implements IRetryAnalyzer{

	int mincount=0;
	int maxcount=3;
	@Override
	public boolean retry(ITestResult result) {
		
		while(mincount<maxcount) {
			mincount++;
			return true;
		}
		
		return false;
	}
	
}

Extent report 
----------------
An extent report in testng is an HTML based document that provides detailed and interactive test execution 
reports . 
It'is an open source reporting library that can be used to create visually appealing reports for selenium test. 


dependency -> extentreports -> 5.0.9


example 1
-----------
package extentReportDemo;

import org.testng.annotations.AfterTest;
import org.testng.annotations.BeforeTest;
import org.testng.annotations.Test;

import com.aventstack.extentreports.ExtentReports;
import com.aventstack.extentreports.ExtentTest;
import com.aventstack.extentreports.Status;
import com.aventstack.extentreports.reporter.ExtentSparkReporter;

public class ExtentReportsDemo {

	ExtentReports extent;
	ExtentTest test;
	@BeforeTest
	public void start() {
		ExtentSparkReporter spark = new ExtentSparkReporter(System.getProperty("user.dir")+"\\Report\\extentReport.html");
		extent = new ExtentReports();
		extent.attachReporter(spark);
	}
	
	@Test
	public void signIn() {
	 test=extent.createTest("signIn page test");
	 test.log(Status.PASS,"sign in page got pass");
	}
	
	@Test
	public void homePage() {
		test=extent.createTest("Homepage test").assignAuthor("oranium").assignCategory("smoke").assignDevice("chrome");
	
		test.pass("user is on home page succesfully");
	}
	
	@Test
	public void productPage() {
		test=extent.createTest("product page test").assignAuthor("product").assignCategory("sanity").assignDevice("chrome");
		test.fail("product page test case got failed");
	}
	
	
	@AfterTest
	public void tear() {
		extent.flush();
	}
	
	
}
